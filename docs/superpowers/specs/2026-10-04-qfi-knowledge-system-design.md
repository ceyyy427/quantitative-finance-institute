# Quantitative Finance Institute 知识系统设计规范

## 目标

把 Quantitative Finance Institute 建设成面向数学学院、计算机学院、金融与运筹学学习者的可搜索、可验证、可连接的量化金融知识站点。站点必须把数学推导、金融含义、算法实现、数值计算、策略研究和风险控制放在同一条学习链上。

第一阶段的可交付垂直链是：

```text
Black-Scholes
  → Greeks
  → Delta 对冲
  → Monte Carlo
  → VaR/CVaR
```

这条链必须同时包含定义、假设、推导、核心结论的完整证明、手算例子、完整 Python 代码、测试、练习答案和跨章节链接。

## 用户与学习结果

### 目标用户

- 数学专业学生：需要看到定义、定理、证明和概率结构。
- 计算机专业学生：需要看到数据结构、算法、数值误差、测试和可运行代码。
- 金融与经济专业学生：需要理解无套利、定价、对冲和风险解释。
- 运筹学与机器学习学习者：需要理解优化建模、约束、泛化和时间序列验证。

### 学习结果

读者完成一条知识链后，应该能够：

1. 说明每个模型的假设和适用边界。
2. 从随机模型推导定价公式或风险指标。
3. 用手算例子验证关键公式。
4. 运行完整代码并解释输出。
5. 用测试检查数学恒等式、数值收敛和边界情况。
6. 解释一个章节如何依赖前置知识，以及如何连接到下一个问题。

## 知识域与目录策略

现有章节路径保持稳定，新增索引和专题页，不做破坏性的大规模重命名。知识域用元数据和知识地图表达：

```text
数学基础 → 随机模型 → 随机微积分 → 资产定价 → 衍生品
       ↘ 统计与时间序列 → 波动率与风险
线性代数 → 凸优化与组合优化 → 组合风险与交易约束
计算机基础 → 数值计算与软件工程 → 可复现研究
机器学习 → 时间序列验证 → 策略研究与回测
```

后续目录预留以下稳定入口：

- `docs/00-foundations/`：概率、统计、线性代数、微积分、数值基础。
- `docs/01-stochastic-processes/` 与 `docs/02-stochastic-calculus/`：随机过程和 Itô 工具。
- `docs/03-asset-pricing/` 与 `docs/05-derivatives/`：无套利、定价、Greeks 与对冲。
- `docs/06-numerical/`：Monte Carlo、有限差分和数值误差。
- `docs/07-portfolio-risk/`：组合优化、VaR、CVaR 和交易约束。
- `docs/08-time-series/`：金融时间序列、波动率和风险回测。
- `docs/09-computer-science/`：数据结构、算法、数据工程和研究软件工程。
- `docs/10-operations-research/`：线性规划、二次规划、整数规划、动态规划和鲁棒优化。
- `docs/11-machine-learning/`：监督学习、特征工程、时间序列交叉验证和深度模型。
- `docs/12-strategies/`：策略假设、信号、组合构建、回测、成本和风险。
- `docs/13-capstones/`：跨领域完整项目。

## 页面契约

每个正式知识页必须使用统一 YAML 元数据：

```yaml
title: 页面标题
status: draft | reviewed | stable
last_reviewed: YYYY-MM-DD
domain: [数学, 金融]
skills: [推导, 编程, 数值验证]
level: foundation | intermediate | advanced
prerequisites: [页面标题]
related: [页面标题]
next: [页面标题]
```

页面正文按以下顺序组织：

1. 学习目标、难度、预计时间和先修知识。
2. 知识关联：上游、当前能力、下游应用。
3. 问题背景与直觉。
4. 符号表、假设、数据和单位。
5. 定义、命题和完整推导。
6. 核心定理的完整证明；依赖更高阶理论的结果必须明确标注证明级别和前置章节。
7. 手算示例，逐步代入数字。
8. 完整可运行代码，代码放入 `src/quantmath/`，页面只展示关键片段并链接源码。
9. 数值验证、测试和误差解释。
10. 模型限制、数据泄露、交易成本和风险提示。
11. 练习题与折叠式详细答案。
12. 参考文献和下一步学习。

## 技能融合与搜索

站点继续使用 MkDocs Material 内置搜索，并通过 `domain`、`skills`、`level`、`prerequisites`、`related` 和 `next` 元数据提高可发现性。`docs/knowledge-map.md` 作为关系总入口，新增领域索引页按学习问题提供入口：

- “我想从数学进入量化金融”
- “我想从 Python 进入策略研究”
- “我想学习组合优化和风险控制”
- “我想理解机器学习如何避免时间序列泄露”

每个页面的“知识关联”区必须至少链接一个上游页面和一个下游页面，避免孤立文章。

## 代码与验证契约

- Python 版本保持 `>=3.11`。
- 生产代码只使用项目已有依赖，新增依赖必须说明原因并更新 `pyproject.toml`。
- 随机模拟必须接受 `seed`，并返回估计值与标准误或置信区间。
- 数学函数必须检查输入域，例如期限、波动率、置信水平和协方差矩阵维度。
- 测试必须覆盖公式恒等式、已知极限、数值误差、空输入或非法输入。
- 页面中的代码示例必须可以从干净环境运行，不得使用隐藏状态或未声明数据文件。
- 策略章节必须使用时间顺序切分或滚动验证，并明确禁止未来数据泄露。
- CI 必须继续通过 Ruff、Pytest 和 `mkdocs build --strict`。

## 第一条垂直链的具体内容

### Black-Scholes 与 Greeks

- 统一符号和无套利假设。
- 从风险中性定价或 PDE 推导公式。
- 给出 Delta、Gamma、Vega、Theta、Rho 的定义、推导和单位解释。
- 用有限差分与解析 Greeks 做数值对照。

### Delta 对冲

- 从一阶 Taylor 展开解释 Delta 对冲。
- 说明离散再平衡误差和 Gamma 风险。
- 给出完整模拟代码、误差统计和交易成本扩展接口。

### Monte Carlo

- 从风险中性下的终值期望建立估计量。
- 证明样本均值无偏和标准误公式的来源。
- 展示方差收敛、随机种子和置信区间。

### VaR/CVaR

- 区分历史法、参数法和模拟法。
- 给出分位数、尾部期望和损失符号约定。
- 解释 VaR 的非次可加性以及 CVaR 的优化意义。
- 用 Monte Carlo 与历史收益做交叉验证。

- 完善 Greeks、Monte Carlo、Markowitz、VaR/CVaR 和时间序列页面。
- 增加 Delta 对冲页面和对应可测试代码。
- 每页补充推导、手算、代码、测试和答案。

### 阶段 C：跨领域扩展

- 补充计算机科学、运筹学、组合优化和机器学习入口。
- 引入无泄露的时间序列交叉验证和策略回测基础设施。

### 阶段 D：综合项目

- 发布从数据、建模、优化、回测到风险报告的端到端项目。
- 每个项目提供数据来源、可复现实验、测试和局限性说明。

## 质量与风险边界

- 内容用于学习和研究，不构成投资建议。
- 所有策略结果必须同时报告交易成本、样本区间、验证方式和失败条件。
- 不把一次回测结果描述为未来收益保证。
- 参考文献使用可点击的出版社、DOI 或官方文档地址。
- 页面状态为 `draft` 时，不宣称内容已完成审校。
